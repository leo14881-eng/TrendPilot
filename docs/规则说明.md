# TrendPilot MVP 规则说明

> 对应代码版本：MVP（第一期），参数版本 `v1-2026-10-14`，全部参数在 `src/main/resources/application.yml` 的 `trendpilot.strategy` 下。
> 业务规则沿用原系统主逻辑；原说明里没有给出公式的地方（加速度、量能、压缩、评分、RR），本文给出重写版的明确定义，标记为 **【重写定义】**。
> 所有 BUY/ADD/SELL 都是影子模拟，`capital_authority = NONE_SHADOW_ONLY`。

## 1. 运行节奏（越南时间）

| 任务 | 时间 | 内容 |
|---|---|---|
| Discovery | 每小时 :17 | 全市场扫描 → EARLY → 系统风险 → 买入/加仓审核 → 资金分配 → 记账 |
| Monitor | 每 5 分钟 | 每个持仓拉新鲜盘口和 K 线，按退出顺序判定 |
| 自检 | 每小时 :07、:37 | Monitor 超过 15 分钟、Discovery 超过 90 分钟未运行则发 Telegram |
| 每日汇总 | 每天 21:00 | 持仓、占用资金、已实现盈亏、任务状态 |

## 2. 标的全集

Binance 现货：状态 TRADING、允许现货、USDT 计价；排除稳定币、法币、黄金代币和人工黑名单；价格和 24h 成交额必须大于 0。不设市值、成交额或数量门槛。

缺 K 线的标的超过 5%，或 BTC 基准缺失，本轮记为 `PARTIAL_DATA`，只记录信号，不做新买入。

## 3. EARLY 信号（六个条件至少命中两个）

只使用截面之前**已收盘**的 K 线；1h K 线最后一根超过 65 分钟、15m 超过 20 分钟视为过期，记为缺数据。

| 条件 | 定义 | 阈值 |
|---|---|---|
| REL_1H | 最近 2 根小时 K 线首开至末收的收益 − BTC 同口径收益 | ≥ 0.8 个百分点 |
| REL_4H | 最近 5 根小时 K 线同口径相对收益 | ≥ 1.5 |
| ACCEL **【重写定义】** | 本段 REL_1H − 前一段（再往前 2 根）REL_1H | ≥ 0.5 |
| VOLUME **【重写定义】** | 最近 4 根 15m 成交额 ÷ 之前 16 根每 4 根的平均成交额 | ≥ 1.35 |
| COMPRESSION **【重写定义】** | 第 −24 至 −7 根小时 K 线平均波幅 ÷ 最近 6 根平均波幅 | ≥ 1.2 |
| MOMENTUM | 最近一根 15m 收益 ≥ 0 且 REL_1H ≥ 0.25 | |

**评分【重写定义】**（满分 10）：REL_1H 最多 3 分（达到阈值 2 倍得满分）、REL_4H 最多 2 分、ACCEL 最多 2 分、VOLUME 最多 2 分、COMPRESSION 最多 1 分。EARLY 本身不要求分数，分数 8 是买入审核门槛。24h 涨幅只做标签，不触发买入。

## 4. 买入审核（Capital Review）

按顺序判定，只有最终 **BUY** 才能分配资金：

1. **SYSTEM_BLOCKED**：扫描不完整、系统风险不允许新增（BTC 1h 跌超 3% 或亏损冻结）、盘口缺失。
2. **REJECT**：黑名单；EARLY 命中不足 2 个；评分 < 8；1h 相对 < 0.8 且 4h 相对 < 1.5；信号或盘口超过 60 分钟；价差 > 50 bps；中间价 ±2% 内任一侧深度 < 30,000U；1,000U 模拟买入滑点 > 75 bps；24h 涨超 20% 时要求 1h 相对 ≥ 1.6 且加速度 > 0。
3. **WAIT**：RR 不足（高于首次 EARLY 价 12% 以上时 RR 要求 2，否则 1.5）；卖出后 60 分钟内再入场；加仓条件不满足。
4. **BUY**。

**RR 成本情景模型【重写定义】**：成本 = 双边手续费 + 双边滑点；上行情景 = clamp(4 × 1h 平均波幅, 2%, 15%) − 成本；风险情景 = 2.5% + 成本；RR = 上行 ÷ 风险。2.5% 是风险测算，不是止损线。

**研究缺口**：MVP 没有接解锁/供给数据，每条审核都记录 `UNLOCK_SUPPLY_DATA_NOT_COVERED`，既不作为拒绝理由，也不作为通过理由。

## 5. 资金与加仓（V2）

- 硬顶 20,000U：普通资金池 17,000U + 战略储备 3,000U（MVP 不动用储备）。每笔 1,000U，每币最多 3 笔。
- 可用额度 = min(17,000, 20,000 × 市场状态比例) × 亏损恢复系数 − 已占用成本 + min(0, 已实现盈亏)。市场状态比例：RISK_OFF 60%、NEUTRAL 75%、CONSTRUCTIVE 85%、STRONG 95%。浮盈不扩大资金池；资金不足就等待。
- BUY 与 ADD 一起按评分排序争取预算。
- **加仓**：必须重新通过全部审核；当前价低于上一笔至少 max(1.5%, 1h 平均波幅) + 往返成本，第三笔 × 1.5；距上一笔信号至少 15 分钟；新的 generation；不在 LOSS_RECOVERY 中。

## 6. 系统风险

- **市场状态**：BTC 24h ≤ −5% 或 4h ≤ −2.5% 或上涨标的占比 < 25% → RISK_OFF；BTC 24h ≥ 3% 且占比 ≥ 65% → STRONG；BTC 24h > 0 且占比 ≥ 50% → CONSTRUCTIVE；其余 NEUTRAL。
- **市场冲击**：BTC 最近 1h 跌超 3%，本轮不新增 BUY/ADD。
- **亏损冻结**：24 小时内亏损退出 ≥ 3 次冻结新增；= 2 次额度减半。随时间窗口滑出自动分阶段恢复。
- BTC 或市场广度数据缺失时保守处理：不新增风险，不凭空构造冲击。

## 7. 退出（Monitor，每 5 分钟）

所有净利都按**全数量盘口逐档模拟卖出**计算（扣手续费、减去含费成本）。任何持仓的交易状态或盘口拿不到，本轮整体停止。

1. **硬失效**（允许亏损退出）：停止交易/下架、黑名单、价差 > 300 bps、模拟滑点 > 300 bps、±2% 买盘深度 < 5,000U、盘口吃不下全部数量。
2. **利润保护**：原始收益 ≥ 2% 且净利 > 0 时启动；底线 = max(本金 0.35%, 最高可退出净利 − 本金 2%)，只上调；净利跌破底线但仍 > 0 时卖出；跳空后净利 ≤ 0 只记录一次 `PROTECTION_GAPPED`，不亏损卖出；加仓后重新基准化。
3. **普通论点失效**：弱条件（1h 相对 < 0、4h 相对 < 0、加速度 < 0、最近 15m 收益 < 0）至少两项，且连续三个有效观察 → 有净利卖出，亏损进入 `LOSS_RECOVERY` 观察；信号恢复且不再亏损时解除。K 线缺失的轮次不算有效观察。
4. **8% 复核**：原始收益 ≥ 8% 时，1h 相对 > 0 且加速度 > 0 继续持有，否则卖出。
5. 其他情况继续持有。

没有固定百分比止损，也没有持有时间上限。

## 8. 数据记录

SQLite 文件 `data/trendpilot.db`：

| 表 | 内容 |
|---|---|
| shadow_event | 影子事件（BUY/ADD/SELL/PROTECT_ARM/PROTECTION_GAPPED/LOSS_RECOVERY），只追加 |
| position | 当前持仓与保护状态 |
| signal_log | 每轮 EARLY 信号 |
| decision_log | 每条审核结论、理由、是否获得资金 |
| job_run | 每次运行；程序是否成功 与 数据是否完整 分开记录 |
| notification_outbox | Telegram 通知（PREPARED / SENT / FAILED） |
