# BTC 每日短线

> 版本 v3 · 2026-10-14 · 只做现货、不止损、允许加仓；新增市场与宏观过滤（参数版本 btc-v2-2026-10-14）
> 纯影子模拟，不下单。独立账本（btc_daily_*），不和 V1/V2 资金混用。资金上限第一个月（至 2026-11-14）10000 USDT。

## 0. 规则一览（具体条件）

符号：**开盘价** = 当天 BTC 日线开盘价（越南时间 07:00）；**ATR** = 近 14 天平均真实波幅；**EMA20** = 近 20 天收盘价均线；**均价** = 持仓总成本（含买入手续费）÷ 持仓数量。所有判断用已收盘的 15 分钟 K 线（每 15 分钟检查一次）。

| 类别 | 条件 | 动作 |
|---|---|---|
| **买入**（第 1 档） | 当前空仓，且当天还没完成过一轮；15m K 线最低价 ≤ 开盘价 − k × ATR（昨收 > EMA20 时 k = 0.25，否则 k = 0.6） | 买入 3000 USDT |
| **加仓**（第 2 档） | 已买第 1 档；最低价 ≤ 第 1 档价 − 0.5 × ATR | 再买 3000 USDT |
| **加仓**（第 3 档） | 已买第 2 档；最低价 ≤ 第 1 档价 − 1.0 × ATR | 再买 4000 USDT（合计 10000，满额后不再买） |
| **加仓间距** | 每次加仓价还必须 ≤ 上一笔**实际成交价** − 0.5 × ATR（开盘已跳到档位下方、按开盘价成交时，下一档顺延，不会连续加仓） | 2026-10-14 修复 |
| **跨天加仓** | 仓位跨天没卖、档位没用完 | 剩余档位改挂在"上次买入价 − 0.5 × ATR、− 1.0 × ATR" |
| **止盈 / 卖出**（当天开的仓） | 15m K 线最高价 ≥ 均价 ×（1 + max(0.5 × ATR ÷ 开盘价, 0.8%)） | 全部卖出 |
| **止盈 / 卖出**（跨天的仓） | 最高价 ≥ 均价 × 1.003 | 全部卖出（扣手续费和滑点后约 +0.18%，回本离场） |
| **止损** | **无**（按你的决定） | 亏损时不卖，只等回本 |
| **超时** | 当天没卖掉 | 不强制卖出；只把止盈目标从 ≥ 0.8% 降到 +0.3%，尽快回本 |
| **每日限制** | 当天已止盈卖出 | 当天不再开新仓，等次日 07:00 新计划 |
| **同一根 K 线** | 既碰到止盈又碰到买入档 | 只算止盈，不买（保守） |

**例子**：开盘 60,000，ATR 2,000（3.33%），昨收低于 EMA20（偏弱，k = 0.6）

- 第 1 档 58,800 买 3000；第 2 档 57,800 加 3000；第 3 档 56,800 加 4000。
- 止盈幅度 = max(0.5 × 3.33%, 0.8%) = 1.67%。只买了第 1 档时，均价约 58,871（含手续费和滑点）→ 涨到约 59,852 全部卖出，赚约 +46 USDT（扣双边手续费后）。
- 三档都买满时，均价约 57,757 → 涨到约 58,720 全部卖出。
- 当天没涨到：次日起涨到 均价 × 1.003（约 57,931）就卖，10000 USDT 仓位约赚 +18 USDT。

成交价：买入按档位价（K 线开盘已低于档位时按开盘价），卖出按止盈价（开盘已高于止盈价时按开盘价）；另计手续费单边 0.1%、滑点 2 bps。

## 0.1 市场与宏观过滤（只决定当天是否开新一轮、开多大）

每天 07:00 生成计划时检查。已有仓位不受影响：照常加仓、照常止盈，仍然不止损。

| 数据 | 免费来源 | 用哪天的数据 | 条件 → 动作 |
|---|---|---|---|
| 下跌趋势 | Binance 日线 | 昨天收盘 | 昨收 < EMA20 < EMA50 且 EMA20 比 5 天前低 → **不开新一轮** |
| 美联储议息决议日 | 美联储官方日程（写在配置里） | 当天 | 当天 → **不开新一轮** |
| CPI 发布日 | FRED 发布日程（需免费 key） | 当天 | 当天 → **不开新一轮** |
| BTC 现货 ETF 净流入 | Farside 公开页面 | 两天前及更早的最近交易日（公布有延迟） | 3 个交易日合计流出 ≥ 10 亿美元 → **不开新一轮**；单日流出 ≥ 3 亿美元 → **减半** |
| 资金费率 | Binance 合约 `/fapi/v1/fundingRate` | 昨天平均 | ≥ 0.03%/8h（多头拥挤）→ **减半** |
| 恐惧贪婪指数 | alternative.me | 昨天 | ≥ 80（极度贪婪）→ **减半** |
| 美国 10 年期利率 | FRED DGS10（需 key） | 两天前及更早 | 5 个观测日上升 ≥ 0.2 个百分点 → **减半** |
| 美元指数 | FRED DTWEXBGS（需 key） | 两天前及更早 | 5 个观测日上涨 ≥ 1.5% → **减半** |
| 合约持仓量 | Binance `/futures/data/openInterestHist` | 昨天 | 只记录（免费历史只有 30 天，无法回测） |

- 减半可叠加：一条 ×0.5，两条 ×0.25，最低 ×0.25。
- 某个来源取不到：计划里写"数据缺失：xx"，这一条当天不过滤，其他照常。
- 回测同时跑"不加过滤"和"加过滤"，两组结果一起推送 Telegram；没有历史的数据在那段时间视为缺失。
- FRED key 未配置时，利率、美元指数、CPI 日程三项跳过。

## 0.2 执行与记录（供后续分析）

系统自己执行（影子模拟，不真实下单）：买入、加仓、止盈卖出全部自动完成并推送 Telegram。实盘规则**不止损**；止损只作为"候选"在影子里记录"如果止损会怎样"。

| 表 | 内容 |
|---|---|
| `btc_daily_plan` | 每天的计划：开盘、ATR、EMA、三档价格和金额、止盈幅度、过滤结论（不开新一轮 / 减仓乘数 / 原因 / 缺失数据） |
| `btc_daily_trade` | 每笔成交：成交时间、价格、数量、金额、手续费、盈亏、原因（第几档买入 / 加仓 / 当日止盈 / 跨天回本止盈）、当天的过滤说明、参数版本 |
| `btc_daily_round` | 每一轮（开仓到全部卖出）：开仓与平仓时间、持仓时长、买入次数、成本、到手、盈亏和盈亏 %、持仓期间最大浮亏（MAE）和最大浮盈（MFE，相对当时均价）、离场原因、开仓当天的过滤、候选止损（3% / 5% / 8% / 12%）的首次触发时间、假设止损价和假设盈亏 |
| `btc_daily_state` | 当前持仓及本轮进行中的 MAE / MFE / 候选止损记录 |
| `btc_daily_series` | 资金费率、恐惧贪婪、ETF 流、利率、美元指数、CPI 日程等每日数据 |

- 每日快照（23:58，`data/snapshots`）和 `/api/btc-daily` 都包含：当天计划、持仓、各轮汇总（平均持仓时长、最差 MAE、平均 MFE）、"不止损 vs 各候选止损"的总盈亏对比、最近 20 轮和 20 笔成交。
- 每周日策略分析读取快照里的 BTC 账本；样本满 30 轮后才按数据调整参数（包括是否值得加止损），改动按版本记录、可回滚，并在 Telegram 说明。
- 回测推送里也有"不止损 vs 止损 3% / 5% / 8% / 12%"的对比。

## 1. 结论

采用 **"回调分批买入 + 均价止盈"**：每天 07:00（越南时间，BTC 日线收盘）根据昨天的日线算出当天的三档买入价和止盈价，推送到 Telegram。价格回落到哪档就影子买入哪档（第 2、3 档就是加仓），涨到"均价 + 止盈幅度"全部卖出。不设止损：亏损时不卖，继续持有到回本止盈。

为什么从"突破买入"改成"回调买入"：不止损时，追高买入的被套概率更大；在下跌中分批低吸、反弹到均价以上卖出，和"不止损 + 可加仓"更一致。

## 2. 每日流程

**07:00 生成当日计划**

- 读取近 40 根日线（Binance REST，每天 1 次），算 ATR14（14 日平均真实波幅）和 EMA20。
- 趋势：昨日收盘 > EMA20 为偏强，否则偏弱。
- 若当前空仓（开新一轮）：
  - 第 1 档：今日开盘价 − k × ATR，买 3000 USDT（偏强 k = 0.25，偏弱 k = 0.6）
  - 第 2 档（加仓）：第 1 档价 − 0.5 × ATR，买 3000 USDT
  - 第 3 档（加仓）：第 1 档价 − 1.0 × ATR，买 4000 USDT
- 若仍持有昨天没卖掉的仓位：不再开新一轮，只把还没用的档位继续往下挂（上一次买入价 − 0.5 × ATR 一档），合计成本不超过 10000 USDT。
- 止盈价 = 持仓均价（含买入手续费）×（1 + 止盈幅度），止盈幅度 = max(0.5 × ATR%, 0.8%)；仓位跨过一天还没卖，止盈幅度降为 0.3%（扣完手续费仍小赚，尽快回本离场）。
- Telegram 推送：当日计划（三档价格和金额、止盈价、当前持仓、昨日结果、累计盈亏）。

**盘中（每 15 分钟用已收盘的 15m K 线判断）**

- K 线最低价 ≤ 某档价格 → 该档影子买入（开盘就已低于档位时按开盘价成交），推送"买入/加仓"。
- K 线最高价 ≥ 止盈价 → 全部卖出，推送盈亏。同一根 K 线里既碰买入档又碰止盈，只算先持有部分的止盈，新档不买（保守）。
- 每天最多完成一轮：当天止盈后不再开新仓，等次日计划。
- **不止损、不强制亏损离场**。"超时"的处理是降低止盈目标到保本附近，而不是割肉。

**仓位与资金**

- 单轮最多 3 次买入，合计 ≤ 10000 USDT（3000 + 3000 + 4000）。
- 现货、不加杠杆、不做空。
- 手续费单边 0.1%，另计 2 bps 滑点（BTC 深度足够，10000 USDT 以内影响极小）。

## 3. 数据和接口

| 用途 | 来源 | 新增请求 |
|---|---|---|
| 日线（ATR、EMA、开盘价） | Binance `/api/v3/klines?interval=1d&limit=40` | 每天 1 次 |
| 15m K 线 | 现有 `kline_15m` 缓存（Discovery 每轮已加载 BTC，WebSocket 也在写） | 0 次（缺口时由现有加载器增量补） |
| 历史回测（近 1 年 1h K 线 + 日线） | Binance REST | 每个参数版本一次性约 10 次，走现有限速器 |

不需要盘口深度、CoinGecko、DefiLlama，不需要任何付费接口或 API key。

## 4. 衡量效果

每天计划消息和 `/api/btc-daily`、每日快照（23:58）里都有：

- 已实现盈亏、未实现盈亏、完成轮数、胜率（不止损下几乎都是"赢"，所以更要看下面几项）
- **最大浮亏**（USDT 和 %）、**最长持仓天数**、资金占用
- 同期"一直持有 BTC"的收益作为对照

上线时用近 1 年历史自动回测一次（同一套规则代码），结果推送 Telegram，回答"不止损最坏会被套多深、多久"。

**自动优化**：参数（k、档距、止盈幅度、档位金额）按现有授权根据数据自动调整，但必须满足：实盘影子 ≥ 30 轮，且回测和影子两边都更优；每次改动有版本号、可一键回滚，并在 Telegram 说明改了什么和依据。

## 5. 风险说明

- **不止损的代价是深度套牢**：BTC 历史上有过一年以上 −70% 的回撤。资金上限 10000 USDT 用满后不会再加仓，只能等回本，这期间资金被占用，每日计划只会显示"持仓等待止盈"。回测会给出最大浮亏和最长持仓天数。
- 一个月样本少，结果有运气成分。
