# BTC 均线趋势（4 条均线 × 4 份）

用户 2026-10-23 交接的单独程序：BTC/USDT 现货趋势跟踪，本金 20,000 U，计划运行到 2028 年 6 月。
**当前阶段：影子模式（只算不下单），不接任何 API 密钥。** 实盘需要用户另行明确同意。

- 和 TrendPilot 其他功能完全分开（用户要求）：独立包 `com.trendpilot.btctrend`、独立表（`btc_trend_slot` / `btc_trend_trade` / `btc_trend_meta`）、
  独立定时任务（`BTC_TREND`）、独立开关 `trendpilot.btc-trend.enabled`；不并入每日汇总、`/holdings`、`/v2`、`/status`，
  不计入其他账本的资金、风控（亏损冻结、预算等）和统计。架构测试 `ShadowOnlyArchitectureTest` 保证它和其他策略包互不引用。
- 它会在跌破卖出线时**亏本卖出 BTC**（用户已接受）。这是单独资金，不受 BTC 每日短线"绝不卖亏"规则约束；BTC 每日短线规则不变。
- 不碰用户的其他持仓（0.488 BTC 主仓、建仓计划的仓位）。
- 交易所：Bybit（用户 2026-10-23 选定），信号用 Bybit BTC/USDT 现货日线。

## 规则（`docs/btc-trend/trend_ref.py` 为唯一标准）

1. 20,000 U 分 4 份，每份 5,000 U，分别绑定日线收盘价简单均线 SMA75 / SMA100 / SMA125 / SMA150（UTC 日线，均线含信号日 D 当天）。
2. 每天 UTC 00:00 日线收盘后，用刚收盘的日线 D 判断，D+1 开盘执行：
   - 该份是 USDT，且 close_D > SMA_D × 1.02 → 全部买成 BTC；
   - 该份是 BTC，且 close_D < SMA_D × 0.98 → 全部卖成 USDT；
   - 其他不动；历史不足 n 根时该份不动。
3. 4 份独立记账，盈亏各自滚动；手续费 0.1%/笔。
4. 启动：第一次运行时 4 份都是 USDT，用最后一根已收盘日线判断，满足买入条件的份直接买入。

## 运行方式（影子）

- 每小时 :05（UTC）运行一次，取 Bybit 日线 1 次请求。每天第一次拿到"昨天"收盘的日线时（正常是 UTC 00:05 = 越南 07:05）判断并影子成交，
  之后同一天只更新现价，不重复成交（每份记录最近处理过的信号日，重启后从数据库恢复）。
- 只用已收盘的日线：开盘时间 + 1 天 ≤ 现在才算收盘，当天进行中的那根不参与均线和信号。
- **执行价 = D+1 当天 Bybit 日线的开盘价**；当天那根暂时取不到时用 D 的收盘价（两者通常相同），推送里会写明用的是哪个。
- 取不到数据，或最新已收盘日线不是昨天：不动作，当天 Telegram 提醒一次，之后每小时自动重试。
- 只在持有运行权的实例上执行。
- Telegram：每天一条"BTC 均线趋势"（4 份状态、4 条均线和买卖线、当天动作、总价值、相对"一直拿着"的差距）；有买卖时单独推送；
  随时发 `/trend` 查看。服务器状态摘要（GitHub `server-status` 分支）里单独一节。
- 实盘下单（限价 Maker、30 分钟重挂、2 小时市价补完、失败重试、余额不足告警）留在 `TrendExecutor` 接口后面，目前只有影子实现。

## 影子盘对比方法

每天的推送和 `/trend` 都列出信号日、收盘价和 4 条均线。用户把它和 Claude 影子盘（越南时间 07:23 更新）对照：
均线差异 < 0.1% 且买卖信号相同视为一致。Claude 影子盘用 Coinbase BTC-USD 日线，这里用 Bybit BTC/USDT，
两家收盘价有微小差异（通常 < 0.1%），均线差异会更小；只有价格离买卖线非常近时，两边信号才可能不同，出现时逐条说明。
