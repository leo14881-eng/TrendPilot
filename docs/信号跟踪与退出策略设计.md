# 信号跟踪与退出策略设计

> 版本：v0.1 ｜ 日期：2026-10-14 ｜ 状态：用户已批准（2026-10-14，按第 10 节默认值），已实现：`tracking/`（跟踪、统计、离线回放）、`variant/`（影子并行）。实现差异见文末「实现说明」
> 关联：[技术方案.md](技术方案.md)、[规则说明.md](规则说明.md)
> 用户决定（2026-10-14）：**暂不加止损**，先记录数据；止损和时间止损以后根据数据决定。
> 本文只写设计，代码由线程「了解 TrendPilot 文件夹」实现。

## 0. 要回答的问题

用户的判断是：很多山寨币满足信号后会先回撤 10% 左右再创新高，止损太快会被反复洗出去。这个判断目前没有数据，本设计要用影子数据回答：

1. 满足 EARLY 信号后，**多久首次扣费后盈利**？
2. **多久大涨**（达到 +5%、+10%、+20%、+30% 净收益）？
3. **多久到短时高点**，高点有多高，之后回撤多深？
4. 期间**最大回撤**（相对买入价和相对最高点）有多深？
5. 回撤 X% 之后**还能创新高的概率**是多少，要多久？
6. 以上在不同市场状态、信号组合、评分、流动性下是否不同？
7. 据此，止损线、时间止损、回撤跟踪止损应设多少，是否比现行规则（无止损）更好？

## 1. 原则

| 原则 | 具体做法 |
|---|---|
| 只观察，不影响交易 | 跟踪模块只读行情、只写跟踪表，不写 `shadow_event`、`position`，不调用资金分配。用 ArchUnit 测试约束。 |
| 无前视偏差 | 信号特征只用 t0 之前的数据；结果只用 t0 之后的数据；起点价用决策时刻可得的价格，不用当根 K 线最低价。 |
| 无幸存者偏差 | 跟踪**全部** EARLY（含被拒绝、未买入、之后下架的币），不只跟踪买入的币；下架、停牌不删除样本。 |
| 无选择偏差 | 每个样本是否进入统计，由事先写定的规则决定，不按结果挑选。 |
| 扣费口径 | 所有"盈利""大涨"都按扣除双边手续费、点差和冲击成本后的净收益计算。 |
| 参数先登记后检验 | 候选止损参数网格在看验证期数据之前写入本文（第 7 节），不事后加参数。 |
| 不自动改参数 | 结论只作为建议，由用户手动改配置、升参数版本，与现行"优化器冻结"一致。 |

## 2. 样本定义

### 2.1 信号事件（episode）

- **触发**：某轮 Discovery 中某标的满足 EARLY（六条件至少命中两个）。
- **去重**：同一交易所、同一标的，如果过去 **24 小时**内已有一个跟踪中的 episode，本次不新开 episode，只在原 episode 上记一次"重复信号"（次数、时间）。24 小时之后再满足 EARLY，开新 episode，并标记 `is_first_episode=false`、关联上一个 episode。
  - 依据：同一波行情每小时都可能重复触发，若每次都算样本，同一段走势会被重复计数，样本不独立、统计显著性虚高。24 小时为初始值，**需数据校准**：上线 4 周后检查重复信号间隔分布，若多数重复集中在 6 小时内，可缩短。
- **主分析只用每个 episode 的首次信号**；重复信号单独作为一组分析（"第二次信号是否更好"）。

### 2.2 两种起点

| 类型 | 起点 | 用途 |
|---|---|---|
| `SIGNAL` | 首次 EARLY 的决策时刻 | 回答"信号本身后的表现"，覆盖全部 EARLY（V1 宽口径的上位集） |
| `V2_ENTRY` | V2 实际影子买入（含 ADD 的每一笔）的成交时刻 | 回答"实际可执行买入后的表现"，与账本对应 |

V2 往往比首次信号晚（审核、资金排队），两者分开统计，不混用。

### 2.3 交易所

Binance 与 Bybit 分池统计（`exchange` 字段）。Bybit 样本使用 Bybit 自己的 BTC 基准；同一 ticker 在两个交易所各算各的，不合并、不互相补数据。

## 3. 价格与成本口径

### 3.1 时间

| 符号 | 含义 |
|---|---|
| `t_sig` | 信号截面时刻：计算信号所用最后一根已收盘 15m K 线的收盘时间（如 :15） |
| `t0` | 决策时刻：本轮 Discovery 拿到盘口价格的时刻（如 :17 过几秒） |
| `t` | 之后每根 15m K 线的收盘时刻 |

### 3.2 起点价 P0（买入价）

- `SIGNAL`：**P0 = 决策时刻 t0 的卖一价（best ask）**。Discovery 每轮多发一次全市场 `/api/v3/ticker/bookTicker`（一个请求拿全部标的买一卖一），不额外按币请求。不用中间价，因为真实买入至少要付到卖一。
- `V2_ENTRY`：P0 = 影子账本中这笔的模拟成交均价（已含盘口冲击）。
- 不使用当根 K 线的开盘价或最低价：开盘在 t0 之前（前视），最低价是事后才知道的最优价。

### 3.3 路径数据

- 粒度：**15m K 线**。直接复用现有 `kline_15m` 缓存（Discovery 每小时已为全集更新），**跟踪不额外发 HTTP 请求**。代价是时间分辨率 15 分钟，对"多少小时盈利"足够；比 Monitor 的 5 分钟粗，见 3.5。
- 缓存保留期从 3 天延长到 **9 天**（7 天窗口 + 信号前 1 天特征 + 1 天余量）。按全集约 400 个标的估算，约 35 万行，SQLite 无压力。
- 每个 episode 自己保存一份窗口内的 K 线（`signal_track_bar`），保证以后重算、换规则回放时数据不变，不依赖缓存是否已被清理。
- 路径从 **t0 之后第一根完整 K 线**开始用 high/low。包含 t0 的那根 K 线（如 :15–:30）只用收盘价，因为它的高低点可能发生在 t0 之前。

### 3.4 净收益

对任一时刻的价格 P（用收盘价 C，或检验极值时用 H/L）：

```
r_raw(P) = P / P0 − 1
r_net(P) = [P × (1 − s/2) × (1 − f) − P0 × f] / P0 − i_exit
         ≈ r_raw − f_in − f_out − s/2 − i_exit
```

| 参数 | 取值 | 依据 |
|---|---|---|
| f 单边手续费 | 0.1%（读 `trendpilot.strategy.fee-rate`） | Binance 现货默认 taker 费率，不假设 BNB 抵扣 |
| s 退出点差 | 用 t0 时 bookTicker 测得的点差，整段固定 | 退出时的真实点差拿不到历史数据，用信号时点差近似；**需数据校准**：用 V2 实际退出盘口对比这个近似的误差 |
| i_exit 退出冲击 | 有盘口快照时按 1,000U 全数量逐档模拟；没有时按 24h 成交额分档估算，并记 `impact_source=MODEL` | 分档表初值见附录 A，**需数据校准**：用有盘口的样本回归 |

"首次扣费后盈利"即 `r_net ≥ 0`。

### 3.5 同一根 K 线内的顺序问题

15m K 线只给开高低收，不知道高点和低点谁先出现。规则：

- 计算"先跌后涨"类指标（高点前的最大回撤）时，同一根 K 线内的低点**算在高点之前**（保守，回撤偏深）。
- 计算"高点后的回撤"时，只用高点**之后的 K 线**的低点，不用同一根。
- 回放止损规则时，同一根 K 线既碰到止损又碰到止盈，**按先止损处理**（保守）。
- 每个 episode 记录出现这种情况的 K 线数 `ambiguous_bars`，占比过高的分组在报告中标注。

## 4. 指标精确定义

观察窗口：**主窗口 72 小时，延伸窗口 7 天（168 小时）**。72 小时覆盖大多数短线山寨行情；7 天用于看"先回撤再创新高"是否需要更长时间。窗口长度本身**需数据校准**：若 72 小时内到达窗口最高点的样本在窗口末尾明显堆积，说明窗口太短，延长。

所有"时间"单位为分钟，从 t0 起算；未发生记为空并标记删失（见 5.2）。

### 4.1 盈利时间

| 指标 | 定义 |
|---|---|
| `t_profit` | 第一根收盘价满足 `r_net(C) ≥ 0` 的 K 线收盘时刻 − t0。**主指标**，与 Monitor 看到的现价口径一致 |
| `t_profit_touch` | 第一根最高价满足 `r_net(H) ≥ 0` 的时刻。参考用，偏乐观 |
| `t_arm` | 第一次 `r_raw(C) ≥ 2%` 且 `r_net(C) > 0`，即现行利润保护启动条件 |
| `profit_hold_ratio` | 首次盈利之后到窗口结束，收盘净收益 ≥ 0 的 K 线占比。区分"摸一下就回去"和"站稳" |

### 4.2 大涨时间

| 指标 | 定义 |
|---|---|
| `t_big_5 / 10 / 20 / 30` | 第一次收盘 `r_net(C) ≥ +5% / +10% / +20% / +30%` 的时刻 |
| `t_big_atr3 / atr6` | 第一次收盘 `r_raw(C) ≥ 3 / 6 × ATR1h%`，ATR1h% 为信号前 24 根小时 K 线平均波幅 ÷ 收盘价 |

- "大涨"的**默认口径为净收益 +10%**。依据：与用户说的"先回撤 10%"同量级；现行 RR 模型上行情景上限 15%，8% 复核线也在附近。各档都记录，最终用哪一档由数据决定。
- 波动率归一的档位用于比较不同波动的币：高波动币涨 10% 和低波动币涨 10% 意义不同。

### 4.3 短时高点

用户说的"短时高点"有两种理解，都记录：

**（1）窗口最高点**

| 指标 | 定义 |
|---|---|
| `mfe_24h / 72h / 7d` | 窗口内最高价对应的 `r_net(H)`（最大有利波动） |
| `t_max_24h / 72h / 7d` | 该最高价所在 K 线的收盘时刻 |

**（2）第一个波段高点（主口径）**

从 t0 起维护运行最高价 `M(t) = max(H)`。当某根之后的 K 线最低价 `L ≤ M × (1 − D)`，且 `M` 对应的 `r_raw ≥ g_min`，则把 `M` 确认为第一个波段高点。

| 指标 | 定义 |
|---|---|
| `swing1_time` | 波段高点所在 K 线时刻（事后才知道） |
| `swing1_confirm_time` | 回撤达到 D 的时刻（实时能知道的最早时刻） |
| `swing1_gain` | 波段高点的 `r_net(H)` |
| `swing1_depth` | 从高点到下一次创新高之前的最低点的回撤幅度 |
| `swing1_recovered` | 窗口内是否重新突破该高点 |
| `swing1_recover_min` | 从高点到重新突破的时间 |

参数：**D = 10%（主），同时计算 5%、15%、20%**；**g_min = 3%**（低于此的高点视为噪声，约等于往返成本加一倍 ATR，**需数据校准**）。

### 4.4 回撤

| 指标 | 定义 |
|---|---|
| `mae_72h / 7d` | 窗口内最低价对应的 `r_net(L)`（最大不利波动，相对买入价） |
| `mae_before_profit` | 首次盈利之前的最深 `r_net(L)`：盈利前要扛多深 |
| `mae_before_peak` | 到窗口最高点之前的最深 `r_net(L)`：拿到最大收益前要扛多深 |
| `mdd_from_peak_72h` | 窗口内任意时刻相对此前运行最高价的最大回撤 |
| `t_mae` | 最低点时刻 |

### 4.5 回撤序列

每个 episode 记录所有"从运行最高价回撤 ≥ 5%"的事件（表 `signal_pullback`）：高点时间、高点收益、回撤深度、谷底时间、是否收复、收复用时。这一表直接回答"回撤 10% 以后还会不会创新高"。

### 4.6 固定时点收益

`ret_1h, 4h, 12h, 24h, 48h, 72h, 7d`：对应时刻收盘价的 `r_net(C)`。固定时点不依赖任何路径定义，是最不容易被定义方式影响的基准指标，所有路径指标的结论都要和它对照。

## 5. 统计方法

### 5.1 报告内容

对每个指标报告：样本数、P10 / P25 / **中位数** / P75 / P90、截尾均值（去掉两端各 5%）。不只报平均值：山寨币收益是长尾分布，少数暴涨会把平均值拉高。

时间类指标额外画**累计达成曲线**：横轴为距信号小时数，纵轴为"已达到该事件的样本占比"，如"信号后 12 小时内 x% 的样本首次盈利"。

条件概率表（核心结论）：

| 问题 | 计算 |
|---|---|
| 回撤 D 后还能创新高的概率 | 在出现过 D 回撤的样本中，`recovered = true` 的占比，D = 5/10/15/20/25% |
| 回撤 D 后最终结果 | 上述样本在 72h / 7d 的固定时点收益分布 |
| 到 T 小时仍未盈利，之后还能盈利的概率 | T = 4/8/12/24/48 小时 |
| 浮亏到 −L 后还能回本的概率 | L = 5/8/10/15/20/25% |

### 5.2 删失（数据没看完的样本）

窗口未结束的样本**不能丢弃**，也不能当作"没发生"。时间类指标用 **Kaplan–Meier 生存分析**估计中位数和分位数：窗口内未发生的事件按"在已观察时长处删失"处理。只统计已结束样本会偏向早发生的事件。

### 5.3 下架、停牌、数据缺口

| 情况 | 处理 |
|---|---|
| 窗口内停止交易/下架 | 以最后可交易价格作为后续所有时点价格，标 `DELISTED`；固定时点收益按此计算，不删除样本 |
| K 线缺口 ≤ 2 根 | 记录缺口数，指标照算（缺口内事件可能漏记） |
| 缺口 > 2 根或累计 > 5% | 该 episode 标 `DATA_GAP`，缺口之后的路径指标置空并按删失处理，固定时点收益仅在该时刻有数据时计算 |
| t0 拿不到卖一价 | 不开 episode，记一条缺数据日志；统计中报告这类丢失的数量 |

### 5.4 分组

| 维度 | 分组 |
|---|---|
| 市场状态 | 信号时的 RISK_OFF / NEUTRAL / CONSTRUCTIVE / STRONG |
| 信号组合 | 命中个数（2 / 3 / 4+）；单条件是否命中（REL_1H、REL_4H、ACCEL、VOLUME、COMPRESSION、MOMENTUM 各自命中与否） |
| 评分 | < 6、6–8、≥ 8 |
| 24h 涨幅标签 | < 8%、8–20%、≥ 20% |
| 追涨程度 | 相对该币首次 EARLY 价的涨幅：≤ 12%、> 12% |
| 流动性 | 24h 成交额按样本三分位 |
| 审核结果 | V2 BUY / WAIT / REJECT / SYSTEM_BLOCKED |
| 交易所 | Binance / Bybit |
| 首次/重复 | `is_first_episode` |

**分组只在信号时可知的变量上做**，不能用"之后涨没涨"去分组。

### 5.5 样本量门槛

| 用途 | 门槛 |
|---|---|
| 分组可在报告中展示 | n ≥ 30，且来自 ≥ 10 个不同标的、≥ 7 个不同自然日 |
| 可用于决定参数 | n ≥ 100，来自 ≥ 20 个标的，时间跨度 ≥ 4 周，至少覆盖两种市场状态 |
| 不达标的分组 | 照常记录，报告中只写"样本不足"，不给结论 |

要求不同标的和不同日期，是因为同一天的信号往往一起涨跌（板块联动、BTC 带动），30 个同一天的样本实际只相当于很少几个独立观察。

### 5.6 置信区间

用**按自然日分块的 bootstrap**（整天的样本一起重抽，2,000 次）计算中位数、比例和规则差值的 90% 置信区间。不用普通 bootstrap 或 t 检验，它们假设样本独立，会低估不确定性。

### 5.7 防止过拟合

- **时间切分**：按信号时间，前 60% 为校准期，后 40% 为验证期。参数只在校准期选，验证期只检验一次。之后每 4 周向前滚动（walk-forward）。
- 候选参数网格事先写死（第 7 节），总组合数控制在 100 以内。
- 结论要求邻近参数也成立（见 8.1 第 4 条），不接受只有单一参数点好的"尖峰"。

### 6.2 `signal_track_bar`（每个 episode 窗口内的 15m K 线副本）

`episode_id, bar_close_time, open, high, low, close, quote_volume`，主键 `(episode_id, bar_close_time)`。7 天 672 行；按每天 30 个 episode 估算，每年约 700 万行，可按年归档。

### 6.3 `signal_outcome`（每个 episode 一行，每次跟踪任务重算并覆盖）

第 4 节所有指标，加 `observed_minutes`（已观察时长，用于删失）、`calc_version`（计算口径版本）、`computed_at`、各时点 `complete_*` 标记。计算是纯函数：输入 episode + K 线副本，输出指标，便于测试和换口径重算。

### 6.4 `signal_pullback`（回撤事件，见 4.5）

`episode_id, seq, peak_time, peak_gain_net, trough_time, depth_pct, recovered, recover_time`。

### 6.5 `exit_rule_eval`（离线回放结果，见第 7 节）

`run_id, rule_id, params_json, episode_id, exit_time, exit_reason, exit_price, net_return, holding_min, data_split（CALIB/VALID）`。

### 6.6 影子并行账本

不新建账本表，在 `shadow_event`、`position` 增加 `ledger` 字段：`V2`（正式影子）、`V1`、`V2_X_<规则ID>`（退出规则变体）。变体账本**复用 V2 的每一笔买入**，只有退出不同，以便逐笔配对比较。

## 7. 将来的止损与时间止损：候选规则

现行规则为**基准 B0**：无固定止损、无持有时长上限、2% 利润保护、8% 复核、普通论点失效（亏损进入 LOSS_RECOVERY）。所有候选只和 B0 比，并且都是**叠加在 B0 之上**（B0 的其他退出仍生效）。

### 7.1 候选规则族与参数网格（事先登记）

| 编号 | 规则 | 参数网格 | 参数初值从哪来 |
|---|---|---|---|
| S1 | 固定净亏损止损：`r_net ≤ −L` 卖出 | L = 8, 10, 12, 15, 20, 25% | 后文 7.2 的 MAE 分析 |
| S2 | 波动率止损：`r_raw ≤ −k × ATR1h%` | k = 4, 6, 8, 10 | 同上，按波动归一 |
| T1 | 时间止损：持有满 T 小时仍未达到 +g 净收益则卖出 | T = 12, 24, 48, 72；g = 0%, +2% | 7.2 的盈利时间分布 |
| T2 | 时间 + 亏损：持有满 T 小时且 `r_net ≤ −L2` 卖出 | T = 24, 48；L2 = 5, 10% | 同上 |
| P1 | 回撤跟踪：净收益曾 ≥ a 后，从最高点回撤 ≥ D 卖出 | a = 5, 10%；D = 10, 15, 20, 25% | 4.3 / 4.5 回撤后创新高概率 |
| C1 | 组合：宽 S1（灾难止损）+ T1 | L ∈ {15, 20, 25}，T ∈ {24, 48, 72}，g = 0 | |

共 6 + 4 + 8 + 4 + 8 + 9 = 39 组，在 100 组以内。

P1 与现行 2% 利润保护重叠：P1 在利润保护之外**另行**生效，用来回答"现行保护底线（最高净利 − 本金 2%）是否太紧，会不会在 10% 回撤中被洗掉"。如果数据表明应放宽，修改的是利润保护参数本身，而不是叠一条新规则。

### 7.2 参数初值的推导方法

**止损线 L（MAE 分析）**：取校准期内"好样本"（72h 内达到 +10% 净收益）的 `mae_before_peak` 分布：

- 设 L 为其 **P90**：止损最多误杀约 10% 的好样本。
- 再看同一 L 在"坏样本"（72h 收益 < 0）上能截住多少亏损：比较坏样本 `ret_72h` 与 `max(ret_72h, −L)` 的差。
- 如果好样本的 P90 回撤已经比坏样本的中位亏损还深，说明这类信号**不适合用固定止损**，结论就是继续不设止损，这本身是有效结果。

**时间止损 T**：取好样本 `t_profit` 的 **P80**，再看"到 T 小时仍未盈利"的样本之后的收益分布。如果这些样本之后盈利的概率明显低于整体，时间止损有意义；如果差不多，就没有意义。

**回撤跟踪 D**：取 5.1 条件概率表中"回撤 D 后仍能创新高的概率"降到 **30% 以下**的最小 D。30% 为初值，**需数据校准**：最终以回放的期望收益决定，不以概率阈值决定。

### 7.3 离线回放

在 `signal_track_bar` 上对每个 episode 逐根 K 线模拟：

- **触发**：按收盘价判断（与 Monitor 看现价一致）；S1/S2 同时用最低价做敏感性检验。
- **成交价**：触发 K 线收盘价 × (1 − s/2 − i_exit) 再扣手续费；若用最低价触发，成交价 = min(止损价, 该 K 线开盘价)，即跳空按开盘价成交，不假设能在止损价成交。
- **同 K 线冲突**：按 3.5，先止损。
- **样本**：分别在 (a) 全部 EARLY 的 SIGNAL 样本、(b) V2_ENTRY 样本上回放；(b) 用于最终决策，(a) 用于在 V2 样本少时补充证据。
- **组合层面**：对 (b) 另做一次带资金约束的组合模拟（20,000U 硬顶、每笔 1,000U、每币 3 笔），因为时间止损会释放资金，影响后续买入，单笔统计看不到这一效应。

### 7.4 比较指标

每条规则对比 B0（同一批入场，逐笔配对）：

| 指标 | 说明 |
|---|---|
| 每笔净收益均值、中位数、截尾均值 | 期望收益 |
| 胜率、盈亏比（总盈利 ÷ 总亏损） | |
| 尾部亏损：P5、CVaR5（最差 5% 的平均） | 止损要改善的主要就是这一项 |
| 组合最大回撤 | 来自 7.3 组合模拟 |
| 平均持有时长、资金周转 | |
| 被误杀的大涨样本比例 | 规则卖出后 7 天内仍达到 +20% 的样本占比 |
| 卖出后再入场次数 | 止损后同一币又出信号再买的情况 |

## 8. 采纳标准与流程

### 8.1 采纳一条新退出规则须同时满足

1. **样本量**：验证期 V2_ENTRY 已结束样本 ≥ 60 笔，SIGNAL 样本 ≥ 100 个，跨度 ≥ 4 周，覆盖至少两种市场状态。V2 笔数不足时，SIGNAL 样本可作为主要证据，但 V2 样本的方向必须一致。
2. **收益或风险显著改善**，满足其一：
   - (a) 每笔净收益相对 B0 的配对差值，90% 置信区间下限 > 0；
   - (b) CVaR5 或组合最大回撤改善 ≥ 20%，且每笔净收益差值的点估计 ≥ −0.2 个百分点（收益基本不变）。
3. **验证期成立**：校准期选出的参数在验证期仍满足第 2 条。
4. **参数稳健**：网格中相邻参数（如 L = 12% 时的 10% 和 15%）也不差于 B0。
5. **不依赖个别样本**：去掉对差值贡献最大的 3 笔后，第 2 条仍成立；把验证期按时间三等分，至少两段方向一致。
6. **分市场状态**：在各市场状态下都不显著差于 B0；若只在某种状态下有效，则作为该状态下的条件规则，且该状态样本需单独达到第 1 条门槛。

### 8.2 流程

| 阶段 | 内容 | 进入下一步的条件 |
|---|---|---|
| ① 记录 | 上线跟踪模块，只记录，不改任何交易规则 | 达到 5.5 中"可用于决定参数"的样本量 |
| ② 离线分析 | 校准期出报告、选 1–3 个候选 | 候选在校准期满足 8.1 第 2、4 条 |
| ③ 影子并行 | 候选作为 `V2_X_<规则ID>` 账本与 V2 并行至少 4 周，入场完全相同 | 验证期满足 8.1 全部条件 |
| ④ 用户确认 | 提交对比报告给用户，用户决定是否采纳 | 用户同意 |
| ⑤ 采纳 | 用户手动修改配置，参数版本升级，变更写入规则说明 | |
| ⑥ 复查 | 采纳后每 4 周复查一次；若连续两次复查新规则差于 B0（按 8.1 第 2 条反向判断），提示用户回退 | |

任何阶段都不自动修改正式 V2 参数。

## 实现说明（2026-10-15）

| 设计 | 实现 |
|---|---|
| 样本、起点价、净收益、15m 路径、9 天缓存 | `SignalTracker`（Discovery 后开样本，每小时 :25 跟踪），`PathCalculator`（纯函数），K 线缓存保留 9 天 |
| 第 4 节指标 | 全部写入 `signal_outcome.metrics`（JSON）；回撤事件写 `signal_pullback` |
| 第 5 节统计 | `TrackingReport`：分位数、截尾均值、Kaplan–Meier、条件概率、分组、展示/决策门槛、按日分块 bootstrap |
| 第 7 节离线回放 | `ExitReplay`（每天 00:20）：39 组候选 + S1/S2 按最低价触发的 10 组敏感性版本，共 49 组；60/40 时间切分；配对差值 90% 区间 |
| 影子并行 | `ParallelExits` + 表 `variant_trade`，规则列表 `trendpilot.tracking.parallel-rules`，默认空 |
| 报告 | 日报一行；周日 21:05 周报；`/api/tracking/summary`、`/api/tracking/rules` |

与设计的差异（都标为【重写定义】，以后可调整）：
- **离线回放的 B0** 只模拟现行利润保护 + 持有到 72 小时主窗口结束；论点失效和 8% 复核需要 BTC 基准与小时信号，离线不模拟。
- **退出冲击**一律按附录 A 的成交额分档估算（`impact_source=MODEL`）；有盘口样本的回归校准留到数据足够后。
- **组合层面模拟**目前只给"每笔 1,000U、按退出时间累计"的组合回撤，没有做带 20,000U 资金约束的再买入模拟。
- **影子并行的回撤**按净收益换算（Monitor 每 5 分钟看到的价格），离线回放按收盘价，两者口径近似。
- 影子并行里，变体提前卖出后，同一持仓后来的加仓不再跟随。
