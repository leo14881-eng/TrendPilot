# V2 盈亏不对称研究（2026-10-23）

起因：用户 2026-10-23 指出"V2 止损的金额远大于止盈，赚好几个还不如一个亏的"，授权"用效果说话，如果回撤数据更好，证明强于改之前的，就可以自己优化"。

- 回测入口：`com.trendpilot.backtest.AsymStudy`（GitHub Actions backtest.yml），原始报告 `backtest-results` 分支 `results/20261023-0439-957ab50/report.md`。
- 数据：币安现货 15m K 线（data.binance.vision），每天成交额前 150 个币，2022-10-01 ～ 2026-10-21。
- 基线：线上现行 v3.4-2026-10-17-altstop，即日线 ATR×1.5 止损（6%～25%，1h 收盘确认，−30% 灾难线）+ 3 天仍亏损等反弹卖 + 冻结修复。买入、风控、资金分配都调用线上同一套类。
- 校准期 2022-10-01 ～ 2025-06-14，验证期 2025-06-15 ～ 2026-10-21。方案都在看结果之前登记。

## 结论

**没有方案通过发布前检查，线上规则不变。**

- 基线的不对称是真实的：平均盈利 +21.95 U，平均亏损 −118.33 U，盈亏比 0.19。85% 的胜率勉强把每笔期望撑到 +1.26 U。
- 亏损主要来自两类卖出：止损 1,079 笔共 −160,990 U，每笔 −14.8%；3 天等反弹卖 1,204 笔共 −108,449 U，每笔 −8.9%。
- 利润保护卖出 11,389 笔，共 +262,222 U，每笔 +2.3%。盈利单平均只卖到最大浮盈的 72%。
- **73% 的亏损单曾经有过浮盈**（最大净利 > 0）：先小赚，没到保护启动线（+2%），又跌回去止损。
- 改卖法的几种办法（放宽保护、按时离场、收紧止损、只在偏强时开仓）都能改变"赚多少、亏多少"的比例，比如 4 小时未走强离场把盈亏比从 0.19 提到 0.73。但**总收益全部低于现行**，多数还转负。
- 只有"止损上限 8%"在验证期更好（+5,163 U，回撤 7,315 U；现行 −4,680 U，回撤 14,310 U），但校准期是 −5,822 U，全期 −659 U，远低于现行的 +19,687 U，不满足"验证期与全期都不差于现行"。
- **需要注意**：现行规则在验证期（最近 16 个月）本身就是亏的（−4,680 U，最大回撤 14,310 U）。卖法调参救不回来，问题更可能在买入信号本身。下一步应查买入端：信号是否有优势、哪些条件下的买入在亏。

## 检查结论

| 要求 | 结果 |
|---|---|
| 验证期与全期合计都 ≥ 现行 | 没有方案满足（全期全部低于 +19,687 U） |
| 最大回撤 ≤ 现行 | 部分方案满足，但收益不满足 |
| 每笔期望提高 | 没有方案满足（现行 +1.26 U 最高） |
| 六种行情无明显变差 | 多数方案至少一种行情明显变差（如保护启动 3%/4% 在"山寨强于 BTC"比现行少 7,000 U 以上） |

不发布。分批止盈（先卖一半、剩下跟踪）需要回测引擎支持部分卖出，这次没有实现，留作后续。
